# 운동·러닝 퀴즈 게임

## 프로젝트 개요

Python 3.10 이상에서 실행하는 터미널 퀴즈 게임입니다. 메뉴에서 퀴즈 풀기, 퀴즈 추가, 퀴즈 목록, 최고 점수 확인, 종료를 선택할 수 있습니다. 추가한 퀴즈와 최고 점수는 프로젝트 루트의 `state.json`에 저장되어 재실행 후에도 유지됩니다. 외부 라이브러리는 사용하지 않습니다.

원격 저장소: https://github.com/Theo-cho311/quiz-game

## 퀴즈 주제와 선정 이유

운동과 러닝을 주제로 선택했습니다. 익숙한 내용으로 문제를 만들면서 Python 입력·출력, 조건문, 반복문, 클래스, 파일 저장을 연습할 수 있기 때문입니다. 기본 퀴즈 5개는 다음과 같습니다.

1. 달리기를 시작하기 전에 하면 좋은 것은?
2. 마라톤 풀코스의 거리는?
3. 달리기에서 페이스(pace)는 보통 무엇을 뜻할까요?
4. 스쿼트는 주로 어느 부위를 단련하는 운동일까요?
5. 육상 경기의 계주에서 다음 주자에게 전달하는 것은?

## 실행 방법

프로젝트 폴더에서 실행합니다.

```bash
python3 main.py
```

메뉴 번호는 1~5, 정답 번호는 1~4를 입력합니다. 아래는 실제 메뉴·목록·점수 출력 형태를 짧게 정리한 예시입니다. 추가 퀴즈와 최고 점수는 각자의 `state.json` 내용에 따라 다릅니다.

```text
운동·러닝 퀴즈 게임에 오신 것을 환영합니다!
1. 퀴즈 풀기
2. 퀴즈 추가
3. 퀴즈 목록
4. 최고 점수 확인
5. 종료
메뉴 번호를 입력하세요: 3
1. 달리기를 시작하기 전에 하면 좋은 것은?
2. 마라톤 풀코스의 거리는?
...
메뉴 번호를 입력하세요: 4
최고 정답 수: 6
메뉴 번호를 입력하세요: 5
게임을 종료합니다.
```

퀴즈를 풀 때에는 각 문제에서 `Quiz.check_answer(user_answer)`가 입력 번호와 저장된 정답 번호를 비교해 `True` 또는 `False`를 반환합니다. 게임은 반환값에 따라 “정답입니다!” 또는 “오답입니다.”를 출력하고 정답 개수를 집계합니다. 실제 플레이 결과는 [퀴즈 풀이 스크린샷](screenshots/06-play-result.png)에 있습니다.

## 기능 목록

- 기본 문제 및 추가한 문제 풀기, 문제별 정답·오답과 전체 정답 개수 표시
- 문제·선택지 4개·정답 번호 입력으로 새 퀴즈 추가
- 퀴즈 목록과 최고 정답 개수 조회
- 빈 입력, 숫자가 아닌 입력, 허용 범위 밖 번호를 안내하고 재입력
- 퀴즈가 없거나 아직 완료한 게임이 없는 경우 안내
- `Ctrl+C` 또는 입력 종료(EOF) 시 안내 후 현재 상태 저장을 시도하고 종료
- 저장 파일이 없거나 읽을 수 없으면 기본 퀴즈 5개로 시작

## 코드 구조와 책임

두 클래스는 서로 다른 데이터를 관리합니다. `Quiz`는 문제 하나의 데이터와 정답 판정을, `QuizGame`은 문제 목록과 최고 점수 및 게임 진행을 관리합니다. 문제 하나를 객체로 추상화하면 동일한 출력·판정·직렬화 로직을 모든 문제에 재사용할 수 있고, 게임 진행이나 저장 방식을 바꾸더라도 문제 자체의 책임과 구분할 수 있습니다.

| 구분 | 위치 | 역할 |
|---|---|---|
| 퀴즈 모델·정답 판정 | `Quiz.__init__`, `show_question`, `check_answer` | 문제·선택지·정답을 보관하고 출력·비교 |
| JSON 데이터 변환·검증 | `Quiz.to_dict`, `Quiz.from_dict` | 객체와 저장용 사전 간 변환 및 저장된 문제 형식 검사 |
| 입력 검증 | `QuizGame.read_number`, `read_text` | 숫자 범위와 빈 문자열 검사·재입력 |
| 게임 진행·메뉴 | `QuizGame.run`, `show_menu`, `play`, `add_quiz`, `show_quizzes`, `show_best_score` | 메뉴 분기, 등록·풀이·점수 집계 및 조회 |
| 파일 입출력 | `QuizGame.load_state`, `save_state` | UTF-8 JSON 로드·저장과 파일 오류 처리 |

## 데이터 파일과 저장·복구

`state.json`은 프로젝트 루트에 UTF-8 JSON으로 저장됩니다. JSON은 사전(dict)·목록(list)의 구조와 필드 이름을 사람이 읽기 쉽게 표현합니다. 다만 퀴즈 전체를 한 번에 읽고 다시 쓰므로 데이터가 많아지면 비용이 증가합니다.

- `quizzes`: 퀴즈 목록. 각 항목의 `question`은 문제, `choices`는 선택지 4개, `answer`는 1~4의 정답 번호입니다.
- `best_score`: 한 게임에서 맞힌 최고 정답 개수. `null`이면 완료한 게임이 없습니다.

```json
{
  "quizzes": [
    {
      "question": "달리기를 시작하기 전에 하면 좋은 것은?",
      "choices": ["준비운동", "바로 전력 질주", "움직이지 않기", "신발 벗기"],
      "answer": 1
    }
  ],
  "best_score": null
}
```

`QuizGame`을 생성할 때 `load_state()`가 기존 파일을 읽습니다. 파일이 없으면 기본 문제로 시작합니다. 퀴즈 추가 직후와 기존 최고 점수를 갱신한 직후 `save_state()`가 호출됩니다. 종료 메뉴(5)는 이미 저장된 상태로 종료하며, `Ctrl+C`·EOF로 입력이 중단되면 한 번 더 저장을 시도합니다. 일반적인 SIGTERM에는 별도 종료 처리기가 없습니다.

저장할 때 `state.json.tmp`에 먼저 JSON을 쓰고 `state.json`으로 교체합니다. 이는 쓰는 도중 기존 파일이 일부만 덮이는 상황을 줄이지만, **버전별 자동 백업은 아닙니다.** 파일 손상·형식 오류가 나면 안내 메시지와 함께 기본 문제로 시작하며, 손상된 파일을 자동 복구하지는 않습니다. 이후 저장 시 기존 파일이 교체될 수 있으므로, 복구가 필요하면 **프로그램을 종료하고** 기존 `state.json`을 다른 위치에 복사해 둔 뒤 정상 백업본으로 복원하세요. 백업본이 없다면 손상된 파일을 별도로 보관하고 `state.json`을 제거한 후 재실행하면 기본 문제로 시작합니다. `state.json.tmp`는 임시 쓰기 파일이지 복구용 백업본이 아닙니다.

읽기 권한이나 쓰기 권한 문제가 발생하면 안내 메시지가 출력되거나 저장 실패를 알립니다. 이 경우 파일·폴더의 권한과 남은 디스크 공간을 확인하고 문제를 해결한 뒤 다시 실행하세요. 저장 실패 상태로 종료하면 해당 변경이 유지되지 않을 수 있습니다.

## Git 작업 기록

기능별로 메뉴, 문제 모델, 기본 문제, 풀이, 목록, 점수, 등록, 저장, 문서 작업을 나눠 커밋했습니다. 메시지는 `Feat: 변경 내용`, `Fix: 수정 내용`, `Docs: 문서 내용`, `Refactor: 구조 변경 내용`처럼 작업 종류와 구체적인 변경을 적는 형식을 사용합니다. 앞으로도 한 커밋에는 설명 가능한 기능 또는 수정 단위를 담습니다.

`feature/quiz-play` 브랜치에서 퀴즈 풀이를 구현하고 `main`에 병합했습니다. [Git 이력 화면](screenshots/01-git-history.png)의 갈라졌다 합쳐지는 선과 `Merge: 퀴즈 풀기 기능을 main에 병합` 커밋이 그 기록입니다. 별도 폴더에 `git clone`한 뒤 README 변경을 커밋·푸시하고, 원래 작업 폴더에서 `git pull`로 가져오는 실습도 완료했습니다. Git 이력 캡처는 촬영 시점의 13개 커밋을 보여주며 이후 문서·스크린샷 커밋이 추가됐습니다.

## 규모와 변경 영향

현재는 퀴즈 전체를 메모리에 올려 관리합니다. 퀴즈가 n개라면 목록 출력, JSON 로드 및 저장은 각각 대략 O(n) 시간이고 메모리 사용량도 O(n)입니다. 1,000개 이상에 대한 실제 벤치마크는 수행하지 않았으며, 긴 목록을 전부 출력하면 찾기도 어려워집니다. 대량 데이터가 필요하면 목록 페이지 나누기, 문제 검색, 필요한 항목만 읽고 수정할 수 있는 SQLite 저장소와 검색 인덱스를 검토할 수 있습니다. 이 개선안은 아직 구현하지 않았습니다.

| 요구 변경 예시 | 주로 확인·수정할 코드 |
|---|---|
| 정답 판정·점수 산정 변경 | `Quiz.check_answer`, `QuizGame.play`, `show_best_score`; 점수 저장 형태가 바뀌면 `load_state`·`save_state`도 확인 |
| 문제에 힌트 등 필드 추가 | `Quiz.__init__`, `to_dict`, `from_dict`, `QuizGame.default_quizzes`, `add_quiz`와 JSON 예시 |
| 입력 허용 범위·문구 변경 | `QuizGame.read_number`, `read_text`와 해당 호출 위치 |
| 저장 파일 형식·위치 변경 | `STATE_FILE`, `QuizGame.load_state`, `save_state` 및 기존 데이터의 호환성 |
